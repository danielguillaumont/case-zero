## Security and deployment boundaries

- The backend preview requires an explicit `CASE_ZERO_REPLAY_PREVIEW=true` in
  development or test. The frontend Lab requires `CASE_ZERO_LAB_PREVIEW=true`
  in local development. Production exclusion is covered by tests and the
  recorded frontend build check. There is no public hosted Detection Lab
  demonstration in this acceptance scope. [Backend gate](../../backend/app/main.py),
  [frontend gate](../../frontend/src/lib/replay-preview-contract.ts),
  [frontend verification](../roadmap/v25f-detection-lab-comparison-ui.md#verification)
- Authenticated active administrators and analysts use the existing role checks.
  The browser uses server actions with the existing session. The comparison and
  evidence are computed from pinned assets and have no persistent runs or case
  pivots. [Comparison route](../../backend/app/api/routes/comparison_preview.py),
  [server client](../../frontend/src/lib/api.ts)
- The backend-provided digests identify canonical content. Frontend validation
  checks their format and relationships. Independent authenticity or signed
  provenance would require a separate trust mechanism. Built-in diagnostics
  describe grading outcomes. General raw evidence and built-in condition traces
  remain outside the API. [Evidence contract](../roadmap/v25e-evidence-investigation.md)
- Before any public deployment, rotate deployment secrets and invalidate
  superseded credentials. Verify demo isolation, least privilege, rate limits,
  redaction, abuse controls and rollback in a separate deployment review.
  [Roadmap security requirements](../roadmap/CASE_ZERO_V3_MASTER_BUILD_PLAN.md#09--security-privacy-and-threat-model)

## v2.6 handoff, in priority order

1. **v2.6-A: gate the existing synthetic suite.** Run the frontend Node tests
   and ESLint in GitHub Actions alongside the existing build and backend proof.
   Add a reproducible authenticated browser smoke check for the fixed preview
   using test-only identities, with explicit desktop and narrow viewport checks.
   Document pass/fail commands and preserve sanitized proof output. Keep the
   preview production gate closed. The smallest first PR is the Node and ESLint
   CI gate with documented local commands. Track the browser check separately.
2. **Proof report and export.** Define a versioned JSON manifest and readable
   report with canonical hashes, fixture and labels, requested and executed rule
   versions, evaluator versions, measured results, denominators and assumptions.
   Start with the offline fixture and add repeatability, payload limits and
   redaction tests. Require per-object authorization and unauthorized-export
   tests before exposing persisted reports.
3. **Persistence and recovery decision.** Resolve ADR 006 against measured
   hosting limits. Specify ownership and retention, bounded scheduling,
   idempotency, cancellation, failure codes, retry policy and restart recovery.
   Exercise DB disconnects, service interruption, duplicate submission and manual
   recovery before accepting persistent jobs. Carry forward authorized event and
   case pivots, paginated dataset/run/result/evidence browsing, and import/export
   states once durable identities and authorization rules exist.
4. **Operational readiness.** Record job state, duration, row counts, parse and
   rule failures, storage and abuse metrics. Rehearse load, migrations, recovery
   and rollback in a disposable environment. Verify secret rotation, access
   boundaries and approved public-demo scope before deployment. Validate the
   novice-user and accessibility gates before broader acceptance.
